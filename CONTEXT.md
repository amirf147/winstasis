# Domain Glossary: winst

* **Win32 Native Boundary:** The unmanaged C++ layer of the Windows OS (`user32.dll` and `dwmapi.dll`). WinStasis isolates this boundary behind an OS Adapter (`IWindowingEnvironment`) to decouple domain logic from native memory layouts.
* **Per-Monitor V2 DPI Awareness:** Process-level DPI context set via `SetProcessDpiAwarenessContext((IntPtr)(-4))` at startup. Ensures that `GetWindowRect`, `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)`, `GetMonitorInfo`, and `SetWindowPos` operate in unified physical screen coordinates across monitors with disparate DPI scaling.
* **Window State:** The geometric and visual properties of an application on screen (X/Y, Width/Height, ShowCmd).
* **Opaque Window Rule:** WinStasis manages the OS-level container. It does not inspect internal application state, read tabs, or launch processes. If an app is closed, WinStasis expects the user to launch it before restoring.
* **Window Handle (HWND):** The temporary, OS-assigned unique ID for a window.
* **Process ID (PID):** The temporary, OS-assigned unique ID for the running application.
* **Target ID:** A stable, 1-based sequential integer generated by `winst` during a snapshot, used by the CLI to reference a specific window (such as `restore --target 1`).
* **Omniscient Workspace Tracking:** `winst` orchestrates windows across active Virtual Desktops globally. It relies on the `Slions.VirtualDesktop` package to wrap the undocumented `IVirtualDesktopManagerInternal` COM interface.
* **Pinned Windows:** Applications configured via Windows Task View to appear on all desktops. `winst` detects and reapplies this state during restoration.
* **UIPI (User Interface Privilege Isolation):** A core Windows security feature that prevents a standard process (`winst`) from modifying a window owned by an Administrator process. To restore Admin windows, `winst` must run as Administrator.
* **STA (Single-Threaded Apartment):** The required thread state for C# applications interacting with Windows Desktop UI COM components.
* **Workspace Fallback:** If a saved Virtual Desktop GUID no longer exists, or if the undocumented Windows API fails due to an OS update, the window is placed on the currently active workspace.
* **Intra-Session Drift:** When windows are moved or workspaces are closed without restarting applications. HWNDs remain valid during this drift.
* **Two-Pass Hybrid Matching:** The resolution pipeline used during restore. Pass 1 validates active `HWND`s against `IsAppWindow` and matches exact `Process Name` + `Window Title`. Pass 2 provides a fallback matching unallocated windows by `Process Name` alone, filtering empty titles, auxiliary tool windows (`WS_EX_TOOLWINDOW`), non-activating popups/overlays (`WS_EX_NOACTIVATE`), unmanaged `WS_POPUP` surfaces, owned panes, and application-cloaked windows.
* **Contextual Geometry Capture:** Three-way capture branching based on `WINDOWPLACEMENT.showCmd`. Minimized windows (`ShowCmd == 2`) capture `rcNormalPosition` to preserve restored geometry and avoid off-screen coordinates (`-32000, -32000`). Maximized windows (`ShowCmd == 3`) capture `rcNormalPosition` and translate coordinates to the active monitor work area if the maximized monitor differs from the normal position display. Normal and snapped windows (`ShowCmd == 1`) capture visible bounds via `DwmGetWindowAttribute(DWMWA_EXTENDED_FRAME_BOUNDS)` to preserve active snapped column bounds on ultrawide displays.
* **DWM Frame Margin Compensation:** Three-step restoration for normal and snapped windows (`ShowCmd == 1`). Step 1 calls `SetWindowPlacement` with `SW_SHOWNORMAL` (`1`) to transition out of minimized, maximized, or snap-grouped states and trigger target-monitor `WM_DPICHANGED`. Step 2 queries live `GetFrameMargins` (`dwmRect` vs `winRect`). Step 3 expands the clamped visible rectangle by the margins and applies it via `SetWindowPos` in screen coordinates, eliminating border overlaps between adjacent snapped windows.
* **Visible-Space Boundary Clamping:** Clamping saved visible coordinates against `MONITORINFO.rcWork`. Oversized ultrawide windows are clamped in width and height (`Math.Min(targetRect.Width, workArea.Width)`) to prevent window edges from overflowing display boundaries.
* **Exclusive Allocation (`claimedHwnds`):** A transient in-memory registry of claimed window handles during a restore pass. Prevents multiple profile records from binding to or moving the same physical OS window.
* **Execution Model (On-Demand):** `winst` is a manual, point-in-time CLI utility.
* **Profile-Driven Storage:** Layouts are saved as user-named JSON profiles in `%LOCALAPPDATA%\WinStasis\sessions\`. Attempting to save over an existing profile prompts for confirmation unless the `--force` flag is provided.
* **Structured Diagnostic Telemetry:** Activated via `--verbose` or `-v` on `save` and `restore`. Outputs HWNDs, window classes, styles, Win32 vs DWM rects, clamping deltas, frame margins, and match pass reasons.
